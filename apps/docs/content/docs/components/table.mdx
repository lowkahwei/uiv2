### Dynamic

To render a table dynamically, you can use the `columns` prop to pass the columns and `items` prop to pass the data.

<CodeDemo title="Dynamic" files={tableContent.dynamic} />

#### Why not array map?

Using the `items` prop and providing a render function allows [react-aria](https://react-spectrum.adobe.com/react-aria/index.html)
to automatically cache the results of rendering each item and avoid re-rendering all items in the
collection when only one of them changes. This has big performance benefits for large
collections.

You could also use `Array.map` to render the items, but it will not be as performant as using the `items` and `columns` prop.

Example:

```jsx
import {getKeyValue, Table} from "@sytechui/react";

const rows = [...];

const columns = [...];

export default function App() {
  return (
    <Table>
      <Table.Content aria-label="Example table with dynamic content">
        <Table.Header>
          {columns.map((column) =>
            <Table.Column
              id={column.key}
              key={column.key}
              isRowHeader={column.key === "name"}
            >
              {column.label}
            </Table.Column>
          )}
        </Table.Header>
        <Table.Body>
          {rows.map((row) =>
            <Table.Row columns={columns} id={row.key} key={row.key}>
              {(column) => <Table.Cell>{getKeyValue(row, column.key)}</Table.Cell>}
            </Table.Row>
          )}
        </Table.Body>
      </Table.Content>
    </Table>
  );
}
```

> **Note**: To learn more about React Aria collections and how to use them, please check [React Aria Collections](https://react-spectrum.adobe.com/react-stately/collections.html).

### Selection Behavior

By default, Table uses the `toggle` selection behavior, which behaves like a checkbox group:
clicking, tapping, or pressing the <Kbd>Space</Kbd> or <Kbd>Enter</Kbd> keys toggles selection for the focused row.

When the `selectionBehavior` prop is set to `replace`, clicking a row with the mouse replaces
the selection with only that row. Using the arrow keys moves both focus and selection.
To select multiple rows, modifier keys such as <Kbd>Ctrl</Kbd>, <Kbd>Cmd</Kbd>, and <Kbd>Shift</Kbd> can be used.

<CodeDemo title="Selection Behavior" files={tableContent.selectionBehavior} />

### Rows Actions

Table supports rows via the `onRowAction` callback. In the default `toggle` selection
behavior, when nothing is selected, clicking or tapping the row triggers the row action.

This behavior is slightly different in the `replace` selection behavior, where single
clicking selects the row and actions are performed via double click.

<CodeDemo title="Rows Actions" files={tableContent.rowActions} />

### Sorting Rows

Table supports sorting its data when a column header is pressed. To designate that a `Column`
should support sorting, provide it with the `allowsSorting` prop.

Table accepts a `sortDescriptor` prop that defines the current column key to sort by
and the sort direction (ascending/descending). When the user presses a sortable column
header, the column's key and sort direction is passed into the `onSortChange` callback,
allowing you to update the `sortDescriptor` appropriately.

We recommend using the `useAsyncList` hook from [@react-stately/data](https://react-spectrum.adobe.com/react-stately/useAsyncList.html) to manage the data sorting. So make
sure to install it before using the sorting feature.

### Managed Column Geometry

The root `columns` prop controls width, flex, and native pinned-column geometry; it does not render
columns. Pass the same array of currently visible leaf columns, in the same order, to the root,
header, and rows:

```tsx
const visibleColumns = allColumns.filter((column) => column.isVisible);

<Table columns={visibleColumns}>
  <Table.Content aria-label="Users">
    <Table.Header columns={visibleColumns}>
      {(column) => <Table.Column id={column.id}>{column.label}</Table.Column>}
    </Table.Header>
    <Table.Body items={rows}>
      {(row) => (
        <Table.Row columns={visibleColumns} id={row.id}>
          {(column) => <Table.Cell>{row[column.id]}</Table.Cell>}
        </Table.Row>
      )}
    </Table.Body>
  </Table.Content>
</Table>;
```

When hiding or reordering columns, derive a new `visibleColumns` array and use it in all three
places. The Table primitive intentionally does not manage column visibility or ordering state.

### Virtualization

Table uses React Aria Virtualizer to render only rows visible in the viewport. Virtualization is
always explicit: pass `isVirtualized`, a stable `columns` geometry array, fixed
`layoutOptions.rowHeight` and `layoutOptions.headingHeight`, and give `Table.Content` a scrollable
height.

Managed columns may use `pinned: "start"` or `pinned: "end"` — **on native (non-virtualized) tables
only**. Pinned columns keep their natural order and only join the sticky stack when they reach the
corresponding edge, showing a shadow only while a stack is active. `pinned` is silently ignored
when `isVirtualized` is set: the column renders in its normal flow position, with no sticky
behavior, shadow, or background. Native pinned columns and their shadows follow logical
`start`/`end` edges in both LTR and RTL layouts.

If the combined pinned widths leave no scrollable center area, Table adds
`data-table-pinned-width-invalid` to its geometry container and logs a development warning. Resize
or unpin a column instead of automatically shrinking user-defined widths.

When every managed column has a fixed width, `fullWidth` distributes any remaining container space
across those columns. Use `fullWidth={false}` to preserve the exact declared widths. The Table and
an `alignColumns` footer always use the same resolved pixel widths.

> **Note**: Pass a stable `columns` reference — define the array outside the component or memoize
> it with `useMemo`. A new array identity on every render forces the table to recompute column
> geometry and regenerate the pinned-column stylesheet each time, even if the columns themselves
> didn't change.

## Slots

- **base**: Root layout.
- **wrapper**: Default visual wrapper.
- **scrollContainer**: Native horizontal scroll viewport.
- **resizableContainer**: React Aria resize and scroll viewport.
- **table**: Native or virtualized grid.
- **thead**: Header row group.
- **tbody**: Body row group and virtualized clipping container.
- **tr**: Data row.
- **th**: Column header.
- **columnResizer**: Accessible resize handle.
- **td**: Data or row-header cell.
- **tfoot**: External footer.

## Data Attributes

`Table.Content` exposes React Aria interaction state:

- **data-focused**: The grid contains focus.
- **data-focus-visible**: Keyboard focus is visible.

`Table.Body` exposes:

- **data-empty**: The collection has no rows.

`Table.Column` exposes:

- **data-allows-sorting**: Sorting is enabled.
- **data-sort-direction**: The current `ascending` or `descending` direction.
- **data-resizing**: The column is being resized.
- **data-pinned**: The native managed column is pinned to `start` or `end`.

`Table.Row` and `Table.Cell` expose interaction attributes including `data-selected`,
`data-disabled`, `data-hovered`, `data-focused`, `data-focus-visible`, and `data-pressed`.

<Spacer y={4} />

## Accessibility

- Exposed to assistive technology as a grid using ARIA.
- Keyboard navigation between columns, rows, cells, and in-cell focusable elements via the arrow keys.
- Single, multiple, or no row selection via mouse, touch, or keyboard interactions.
- Support for disabled rows, which cannot be selected.
- Column sorting support.
- Async and infinite loading through `Table.LoadMore`.
- Support for both toggle and replace selection behaviors.
- Labeling support for accessibility.
- Ensures that selections are announced using an ARIA live region.
- Support for marking columns as row headers, which will be read when navigating the rows with a screen reader.
- Optional support for checkboxes in each row for selection, as well as in the header to select all rows.
- Automatic scrolling support during keyboard navigation.
- Support for row actions via double click, Enter key, or tapping.
- Typeahead to allow focusing rows by typing text.
- Long press to enter selection mode on touch when there is both selection and row actions.

### Additional compound parts

- `Table.Footer`: an external footer `div`; `alignColumns` uses managed geometry and `isSticky`
  pins it to the scroll-container bottom.
- Column headers show a passive divider by default. Enable `isResizable` to automatically add React
  Aria's keyboard, pointer, and touch-accessible resizing to every column except the last.
- `Table.SelectionCheckbox`: an explicit header or row selection checkbox; accepts a Table color.
- `Table.SortableColumnHeader`: renders the label and sort indicator; accepts `indicator`,
  `showIndicator`, and `sortDirection`.
- `Table.LoadingOverlay`: an absolutely positioned loading layer.
- `Table.Collection`: React Aria's dynamic collection helper.
